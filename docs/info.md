## How it works

A weight-stationary signed INT4 dot product accelerator. With `uio[6]` (LOAD) = 1, 8 bytes load the 16-element weight vector into the chip (two 4-bit values per byte, low nibble first). Then each x vector is 8 bytes with LOAD = 0, one byte per clock: the dot product with the stored weights is 2 MAC per clock. Weights stay until the next load, so many x vectors (a batch) reuse them. CHAIN (`uio[3]`) at the last byte of a vector carries the 32-bit sum into the next vector; the 20-bit saturate is applied once at the end. The MAC is pipelined (operand register, product register, accumulate, saturate).

Design `5b7ae333-52e3-4016-bdbb-da6e3ff1fe51` was verified in chip-lab against a fixed reference model and an RTL scoreboard, then wrapped for the Tiny Tapeout pinout.
Pre-layout sky130 standard cell area is 7875 um^2 and the selected tile size is 1x1 (estimate).

## How to test

Hold `uio[0]` (IN_VALID) with the byte on `ui_in`; it is taken on a rising edge where `uio[4]` (IN_READY) is 1. `uio[6]` = 1 marks weight bytes. After each 8 x bytes the 3-byte result appears on `uo_out`, least significant byte first, with `uio[5]` (OUT_VALID); `uio[2]` (OUT_READY) advances it. Back to back, one vector completes every 8 clocks. `uio[1]` (ABORT) discards a partial vector and sets `uio[7]` (ERR).

`host/pin_client.py` (MicroPython, demo board) has `load(w)`, `batch(xs)` and `batch_dot(w, xs)` for vectors of any length (weights loaded in chunks, partial sums added on the host). The cocotb tests run the same driver against the RTL.
